# 演出手动修改指南

适用于当前序章及第一至第五章。正文与制作配置分开放：对白里不用写图片文件名或音乐编号。

## 先找对文件

以下路径均相对于项目目录 `D:/PROJECT/galgame`。

| 想改什么 | 文件与位置 |
| --- | --- |
| 第一至第五章的对白、旁白、选项文字 | `剧情正文/` 下各章正文 `.md` |
| 旧楼、土豆农场、Grok 画稿独立事件 | `剧情正文/事件/` 下对应 `.md` |
| 新事件插在哪一场之后 | `story/common-expansion.cjs` 的 `inserts` |
| 新事件及第四、第五章的背景、BGM、立绘切换 | `story/common-expansion.cjs` 的 `staging`、`cues` |
| 实际 Token 收支 | 同一文件的 `transactions`；正文可用 `{tokens}` 显示实时余额 |
| 第三章每场开始的背景和 BGM | `story/chapter-three-production.cjs` 的 `staging` |

| 第一、第二章的上述演出 | `tools/build-common.cjs` 的 `staging`、`cues` |
| 各章默认立绘 | `tools/build-common.cjs` 顶部的 `baseLooks` |
| 只显示一句的表情差分 | `tools/build-common.cjs` 的 `expressions` |
| BGM 本身的曲调、速度、音色 | `music.js` 的 `window.SCORES` |

| 普通背景、插画编号与图片对应 | `tools/build-common.cjs` 的 `backgrounds`、`cgNames`；第三章新增背景在 `story/chapter-three-production.cjs` 的 `backgrounds` |
| 序章对白和逐句演出 | `story/chapters/opening.js`、各角色 `.js`、`chapter-finale.js`，以及 `story/routes.js` |

**不要直接修改 `story/chapters/common.generated.js`。** 它是生成结果，下次生成会覆盖手动修改。

文件音乐可以写成 `{name:'曲名', src:'assets/bgm/文件名.mp3', loop:true}`，然后像普通 BGM 一样在 `cues` 使用其编号。第四章对战在“四十一秒”开场切入 `B20-Duel`，在“演示频道关闭”切回 `B13`。段内逐句推进不会重播；离段时文件音乐淡出 1.2 秒，再进入正常配乐。它与现有音乐音量、静音和页面隐藏暂停共用控制。

## 临时添加一个事件

参考 `剧情正文/事件/第二章-今天不打末影龙.md`。文件只放正文，场次标题使用尚未占用的两位数字或带 A-E 的编号，例如 `## 04B · 新事件`。不要使用保留给自由相处分支的 `07A-E`、`09A-E`。

在 `story/common-expansion.cjs` 的 `inserts` 中登记 `{chapter:2, after:'04A', file:'剧情正文/事件/你的事件.md'}`，并在 `staging` 增加 `'2-04B':['场景编号','B07']`。插入表按顺序执行，`after` 可以指向前面已插入的事件。最后运行 `node tools/build-common.cjs`。

新 CG 文件放到 `assets/scene/cg/`，将不含 `cg_` 前缀和 `.png` 后缀的编号加入该配置的 `cgs`；在 `cues` 用一句独特旁白作为锚点切换 `bg`。结束 CG 时再次设置普通背景。角色不会叠在 CG 上。

`transactions` 的 `id` 是防止重复记账的凭据，不要仅为了改显示文字而改它。`amount` 正数为收入，负数为支出；`chapter`、`section` 和 `anchor` 决定在哪一句结算。锚点不存在或出现多次会中止生成，不会默默漏扣。

第五章最终邀请门槛位于 `tools/build-common.cjs` 的 `finalChoice`：好感 40，并完成第四或第五章对应独处事件。锁线保存在 `personalRoute`，序章见证人仍保存在 `route`。

## 每场一开始的背景与 BGM

第三章配置中的这一行：

```js
'3-11':['ch03_old_bridge_evening','B17'],
```

意思是第三章第 11 场，开场使用旧桥背景，播放 B17《这张也留下》。它对应正文的 `## 11 · 倒计时没有等人`。

- `3-07A` 表示第三章第 07 场 A 分支，不是台词序号。
- 数组第一项是场景编号，不是图片完整路径。
- 数组第二项是 BGM 编号；写 `'silence'` 表示静默。
- 这两个设置持续到该场后面的切换指令；进入下一场会重新采用下一场的 `staging`。

本轮三张背景的对应关系：

| 场景编号 | 图片文件 |
| --- | --- |
| `ch03_old_street_day` | `assets/scene/bg/bg_ch03_old_street_day.png` |
| `ch03_bookstall_day` | `assets/scene/bg/bg_ch03_bookstall_day.png` |
| `ch03_old_bridge_evening` | `assets/scene/bg/bg_ch03_old_bridge_evening.png` |

第三章 `backgrounds` 里的第二项是图片缺失时的备用场景，不是实际要显示的图片路径。现在三张正式图片都在，优先使用它们。

## 在某句切换

在对应场次的 `cues` 数组内设置。下面就是第三章 Gemini 切换星图时现有配置的展开形式：

```js
'3-10': [
  ['她将相机挂稳，抬手拨开肩边的长发。', {
    char: 'gemini',
    look: ['gemini', 'gemini_starmap_star_cape_calm'],
    shift: {name: '星图', detail: '核对多组路线与拍摄位置'},
    music: 'B12-Map'
  }]
],
```

正文读到包含这段文字的那一句时，同时显示 Gemini、换成星图立绘、显示模型切换提示，并换音乐。

| 字段 | 作用 | 写法示例 |
| --- | --- | --- |
| `char` | 当前显示哪位角色 | `'gemini'`；旁白句写 `null` 可收起立绘 |
| `look` | 改变某角色在当前场次后续使用的立绘 | `['gemini','gemini_starmap_star_cape_calm']` |
| `bg` | 从这一句起换场景或插画 | `'ch03_old_bridge_evening'` |
| `music` | 从这一句起换 BGM | `'B17'` 或 `'silence'` |
| `shift` | 仅这一句显示模型切换提示 | `{name:'星图',detail:'核对多组路线与拍摄位置'}` |

只改需要的字段即可。例如第三章回程收起人物、夜间停音乐，已有如下配置：

```js
['回程时，没人排出刚才的站位', {char: null}]
['现实那边依旧没有新消息', {music: 'silence'}]
```

这两行分别属于 `3-11` 和 `3-12` 的数组，不是单独粘贴到文件末尾。

### 立绘文件名规则

`look` 第一项是角色小写编号：`chatgpt`、`claude`、`gemini`、`deepseek`、`grok`。第二项是对应目录里的图片名，**不带 `.png`，也不带路径**。

例如 `['gemini','gemini_starmap_star_cape_calm']` 对应 `assets/gemini/gemini_starmap_star_cape_calm.png`。

`look` 不会自行让角色出场，因此在旁白句切换时通常同时写 `char`。五位角色本人说话时，会自动切到说话者；旁白、玩家发言通常保留前一位角色。消息对白不显示实体立绘，已标记为 CG 的画面也不叠加立绘。

`char:null` 适合放在旁白句；如果放在女主本人的发言上，自动显示说话者的规则会覆盖它。

### 切换持续多久

- `look` 在当前场次内保留，直到同一角色再次被设置 `look`；换场后从 `baseLooks` 重新开始。
- `baseLooks` 每一章的五张图按 ChatGPT、Claude、Gemini、DeepSeek、Grok 排列，不能随意交换顺序。
- 目前有两处跨场形态延续的明确设置，在生成工具里搜索 `looks.chatgpt`、`looks.gemini`：第一章第 06 场继续使用 Sol；第三章第 11 场先保持星图，再按旁白换回流星。改这些场次的初始模型时，要一并核对。
- 普通换表情或换衣，只改 `look`；不必加 `shift`。模型切换才配合旁白、主角回应和 `shift`。

### 只想换一句表情

用 `tools/build-common.cjs` 的 `expressions`。例如给第三章第 07C 场添加：

```js
'3-07C': [
  ['这个不用写，我只是拿早了。', 'gemini_meteor_white_jacket_curious']
],
```

这句显示已有的 curious 差分，下一句恢复当前场次的立绘，不会一直保持该表情。它的优先级高于该句的普通 `look`；同一句同时配置两处时请注意检查。

## BGM 本身在哪里

`staging`、`cues` 决定“什么时候播”；`music.js` 决定“这首音乐是什么”。目前是浏览器本地合成配乐，不是 MP3 播放列表。

第三章常用：B10～B14 分别是五位角色主题；B16 是旧街主题；B17 是合照主题；B12-Map 是 Gemini 星图变奏；B15 是轻悬疑。

写 `music:'silence'` 才是主动静默。省略 `music` 在共同篇配置里表示保持该场已有音乐，不表示静默。不要把 MP3 路径直接填入这里；正式音频需要另外接入播放器。

## 改触发句时注意

`cues` 使用“正文中包含这段文字”的匹配方式，每条只在本场第一次匹配时触发。不包含 `旁白：`、`Gemini：` 等说话人前缀。

正文如果改掉这段文字，要同步改 `cues`。找不到时生成会报 `Missing cue` 并给出场次和原文，旧生成文件不会被成功替换。

尽量选本场独有的一小句，避免只写“嗯”“她笑了”。不要重复创建两个同名场次键；已有 `'3-10'` 就在它的数组中追加。

目前演出状态在生成时按正文顺序计算，**不要在可能被跳过的选项分支里切换长期 `look`、`bg` 或 `music` 后指望另一分支自动恢复**。普通分支表情用只影响一句的 `expressions`；持续切换优先放在共同段落，复杂分支需在各分支入口和汇合处明确重设。

## 序章的写法不同

序章尚未使用共同篇的正文生成方式，直接在 `story/chapters/` 对应脚本的台词后面写设置：

```js
['chatgpt', '好。我们先到服务台。', {
  char: 'chatgpt',
  sprite: 'chatgpt_terra_white_dress_calm',
  bg: 'transit',
  music: 'B10'
}],
```

这是写法示例，不是需要新增的剧情。注意序章用的是 `sprite`，不是共同篇 `cues` 的 `look`。

序章每条台词的额外设置只影响这一条；下一条会回到 `sequence(...)` 指定的默认背景、角色，以及默认立绘和序章音乐，不自动继承上一条。要连续保持变化，需给相关台词都设置，或调整对应整段的默认设置。序章 `sprite:'happy'` 等旧简写对应的具体文件在 `game.js` 的 `spriteFile()` 中。

## 修改后怎么生效

修改第一至第三章正文、演出配置、场景编号后，在项目目录运行：

```powershell
node tools/build-common.cjs
```

看到 `Compiled ...` 且没有报错后，刷新游戏页面；可用 Ctrl+F5 强制刷新。只覆盖同名图片、修改 `music.js` 或序章脚本，刷新即可，不需要重新生成共同篇。

建议读档到被修改场次之前查看效果。插入对白会保留未改动段落的既有 ID；改写或删除存档正停留的那一句，旧存档未必还能对应原位置。重要存档先在游戏内导出备份。

需要检查分支时运行 `node tests/common.cjs` 和 `node tests/chapter-three.cjs`。这些浏览器检查依赖当前电脑已有的测试环境，不是游玩的必需步骤。
